# 35. Trackers: the framework and AniList

Status: Accepted (2026-10-04)

## Context
Readers keep lists on AniList, MyAnimeList, Kitsu and MangaUpdates. The tables for it (`tracker_accounts`, `manga_tracks`, `tracker_queue`) have existed since the first migration ([0006](0006-sqlite-drizzle.md)) and backups already carry links without tokens ([0029](0029-backup-and-restore.md)). Reading must never wait for a network, and a tracker must never see what was read while incognito ([0017](0017-incognito-boundary.md)).

## Decision
- **Main owns it.** `apps/desktop/src/main/trackers/`: `TrackerClient` (one per service: `viewer`, `search`, `getEntry`, `save`, with the token passed in), `TrackerManager` (accounts, links, queue), `secret.ts`, `oauth.ts`, `anilist.ts`. Statuses are normalised (reading, completed, on hold, dropped, planning), scores are 0 to 10, progress is the chapter number. Failures are `TrackerAuthError` (login refused), `TrackerRateLimitError` (with how long to wait) or `TrackerRequestError`; anything else is a network problem.
- **One door for reading.** `ProgressRepository.onRead(mangaId)` is called when chapters became read: the reader reaching the end, "mark as read", migration, "mark previous as read". Restores and marking unread do not call it. The manager sends `highestRead` (the highest chapter number read, rounded down; the count of chapters read when none has a number), only when it is higher than the entry's progress, so an entry never goes back. A finished entry stays finished. While incognito the manager says nothing.
- **A queue, not a request.** Each change is written to `tracker_queue` (one row per manga and tracker; a newer change is merged into it field by field). A flush sends what is due, when online, a moment after a change (so a burst goes out as one), every minute, and when the network comes back. A failure keeps the row and retries with growing pauses (a minute, doubling, at most an hour); a rate limit waits as long as the tracker asks; a refused login marks the login expired and holds everything for that tracker until the next login. An edit made while an update is on its way stays queued and goes next.
- **Linking.** A manga is linked from its page (Tracking): search by title, pick the entry. An entry the user already has keeps its status, score and dates, and only the chapters it lacks are sent; a new entry starts as "reading" with what was read, or "planning". Disconnecting keeps links and drops the queue; connecting again resumes. Links are in backups (with the tracker's title, new column `remote_title`, migration 0005), logins never are.
- **Logins in the system browser, through the loopback.** `loopbackLogin` serves `http://127.0.0.1:<port>/callback` for the length of the login. AniList's implicit grant puts the token in the URL *fragment*, which never reaches a server, so that page (ours: one inline script, nothing from outside, a strict CSP) forwards it to `/done`. The server answers only to its own address, takes the first token with the right `state` (when the tracker sends it back), and closes. It replaces the `matane://` deep link BRAINSTORM once planned: registering a protocol is unreliable for AppImage and portable builds. The port is fixed because the app's redirect URL is registered with the tracker; a port in use fails with a message.
- **No client secrets.** The implicit grant needs only the client id, which is public (like Discord's, `client-ids.ts`; `MATANE_ANILIST_CLIENT_ID` overrides it for tests, set but empty switches the tracker off). A secret is never stored in the repository or the app.
- **Tokens are sealed.** `SecretBox` stores them with the system keyring (`enc:`) when there is one and as plain text otherwise (`plain:`), the same convention as the proxy password; Settings → Tracking says when it is plain. AniList tokens last a year and are not refreshed; an expired or refused one asks for a new login. A pasted access token is accepted as a fallback.
- **Requests go through the app's own session** (`sessionFetch(session.defaultSession)`), so DNS-over-HTTPS and the proxy of Settings → Network apply.
- **Tests without a tracker.** Everything runs against a fake AniList (`apps/desktop/e2e/support/anilist.ts`); under `MATANE_E2E` the API address, the login port and the capture of the browser address are replaced.

## Consequences
- Reading stays fast and offline-safe; a tracker that is down only delays its updates, and Settings → Tracking shows what waits and the last problem.
- The renderer cannot show remote cover images (its CSP allows none), so search results are text.
- MyAnimeList, Kitsu and MangaUpdates are further `TrackerClient`s on the same manager; syncing from the tracker back to the app is separate ([plan](../plans/pasca-v1-tracker-lokal-template.md), Milestone 6f).
